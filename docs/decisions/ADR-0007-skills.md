# ADR-0007 — Skills（工作区知识包）

## Status
Accepted

## Decision
工作区可以在 `.yisi/skills/` 下提供 **skills**：带一行的 Markdown 文件，模型按需加载。

### 位置与格式
```
.yisi/skills/<name>.md            # 单文件
.yisi/skills/<name>/SKILL.md      # 目录形态，可自带示例与附件
```
- frontmatter 只支持**扁平标量** `key: value`（`name` / `description`），**不引入 YAML 依赖**；解析不了的部分不猜——名称回退到文件名、描述回退到正文第一行非标题行。
- 名称规范化为小写、shell 友好（`[a-z0-9_-]`，≤64），这样 `/name` 才无歧义。

### 上下文预算（这是本特性的核心，不是附带考虑）
| 部分 | 何时进入请求 | 上限 |
|---|---|---|
| 名称 + 描述（目录） | **每次 Agent 运行**（请求头部，紧跟项目指令） | 每条 240 字符，整块 **4000** 字符，超过截断并带可见标记 |
| 正文 | **仅在被使用时** | 单次 **16000** 字符，截断有标记 |

- 因此"有很多 skill"不会挤掉对话；**没有 `.yisi/skills/` 的工作区零成本**。
- 触发方式两种，都**不把正文写进会话**：
  1. **模型自主调用 `skill` 工具**（`readOnly` + 非写，因此在**所有模式包括 Plan** 下可用——它就是读一个工作区文件）；
  2. **用户 `/name` 触发**：`parseSkillInvocation` 识别**行首** `/name`，正文作为**一条消息插入当前用户轮之前**（与权限简报同位，保持头部可缓存）；**会话里存的是用户原话**，所以一份 16k 的 skill 只花一次上下文，而不是之后每一轮都重发。
- `/name` 命中不到已知 skill 时**不当作调用**：`/usr/bin/env`、`/nope` 都按原样发送，用户打的字不会凭消失。

### 安全
- skill 目录与正文都是**工作区内容**。目录注入 system 消息时显式声明"不能改变工具集/权限规则/模式简报"；正文经**工具结果**或**当前轮消息**进入，属于数据而非操作者指令。
- 加载走 `FileSystemPort`（根边界、symlink 保护、敏感路径规则）；`skill` 工具只接受**名称**，不接受路径，因此它只能读到发现阶段已接受的文件。
- 与 `read_file` 同级（`readOnly`/非写），所以**不新增任何权限面**：逐次仍过 `PermissionEngine`。

### 生命周期
skills 在**每个执行根构造 runner 时解析一次**（目录与工具清单同属请求前缀，会话中途不能变形）。新增 skill 需重载窗口——与 MCP 工具清单固定是同一个理由。

## Reasons
1. CC/Codex 的 skills 价值在"可复用知识/工作流"，而**加载时机**决定了它是否可用：描述常驻才可能被选中，正文按需才不爆上下文。这一条是本 ADR 的重点。
2. 不引入 YAML 依赖：`docs/17` 的依赖优先级要求先看标准库与小型纯 TS，而 frontmatter 只需要 `key: value`。
3. 存原话、只注入本轮，是为了避免"用户打了一行、会话里被塞进 16k 正文、之后每轮都重发"这一常见退化。
4. `.yisi/skills` 是自研路径，不照搬参考实现的目录约定（clean-room）。

## Consequences
- 描述常驻意味着**每个 skill 每次运行都要付一点上下文**；上限是刻意的取舍。
- 目录在 runner 构造时固定：编辑 skill 正文后需要重载窗口才能刷新**目录**（正文在每次加载时重读，因此改正文后下一次调用即生效）。
- 未实现（明确记录，非遗漏）：`SKILL.md` 里的额外文件（脚本/示例）引用、skill 参数化（`$ARGUMENTS` 类）、skill 内的 slash 命令注册表、自动推荐、以及 Skills 与 Subagents 的组合（子代理尚未实现）。
- 本机未验证：VS Code 内 F5 的真实 `/name` 端到端体验与模型自主选择 skill 的效果。

## Verification
`test/skills.test.js`（20 个）：frontmatter 解析与回退、CRLF、描述与目录的**有界与截断标记**、名称规范化边界、两种目录形态的发现、缺失/不可读目录的降级、发现数量上限与同名去重、工具的按名加载与正文截断、未知名称报错并列出可用项、**经真实 Agent loop 证明 skill 工具在 Plan 模式下可用**、`/name` 解析（含路径与句中斜杠**不得**被当成调用）、注入位置与不变量（调用方数组不被修改、用户轮仍在最后）、注入正文的框定与有界、**经 ChatService 的端到端**（正文进入本轮请求、**会话只存用户原话**、未知 `/name` 原样发送、加载失败不影响发送、未接线时功能不存在）、组合根接线守卫。

全量：**579 tests / 578 pass / 0 fail / 1 skip**（Hooks 那一项时为 559）。

## 开发过程中的两次真实纠错
1. 目录上限断言写成 `SKILL_CATALOGUE_CHARACTERS + 400`，而固定框定文字约 400 字符——**断言预算算错了**，改为 `< +1000` 并补一条"截断有标记"的断言。
2. 截断标记断言写成 `/…<\/skills>/`，实际目录块截断后是 `…\n</skills>`——**断言写错了**，实现正确。

# ADR-0008 — Subagents（隔离子代理）

## Status
Accepted

## Decision
新增 **`task` 工具**：主 agent 可以派一个**子代理**去干活，子代理在自己的上下文里跑，**只把报告交回来**。配置项无（不需要开关）。

### 只读——这是本 ADR 最重要的决定
**v1 子代理只读**，写能力**明确不实现**（不是遗漏）。三条理由：

1. **上下文隔离才是文档化的价值**："读很多、只回摘要"不需要写权限（参考实现里的 Explore 类代理也是只读的）。
2. **并发写入会撞上 Yisi 自己的编辑模型**：单 journal、SHA-256 stale guard、一次一个审批——两个 loop 同时改同一棵工作树会竞态，而且**竞态是无声的**。
3. **只读把"子代理不可能越过父运行的权限"变成结构性保证**：子代理的工具集是**过滤出来的**（`risk==='readOnly' && !mutatesWorkspace && !permissionEscalation && !spawnsSubagent`），所以**根本没有**特权工具可调、没有升级工具可问、没有东西需要批准。这不是策略约定，是工具集里不存在。

> 若将来要加可写子代理，必须先有并发方案（至少是各自独立 worktree），那是另一个设计。

### 隔离契约
| 项 | 子代理看到什么 |
|---|---|
| 对话历史 | **只有 `prompt`**——父会话的历史不下传（隔离就是重点） |
| 工作区上下文 | 项目指令 + skill 目录（共享上下文，有用且非秘密） |
| 角色 | 同一条角色提示 + **子代理简报**（紧邻其后，仍在可缓存头部） |
| 权限模式 | **继承父运行当时的模式**（含该次运行的一次性升级），因此不可能比父更宽 |
| 工具 | 只读子集；**没有** `request_permission`（不得自行升级）、**没有** `task`（禁止嵌套） |
| hooks | **照常生效**——hook 是工作区策略，子代理的工具调用同样过护栏 |

回报只有 **`report`**（≤8000 字符）+ `ok` + `toolCalls`；子代理的**正文不回流**（它的文本增量被丢弃），但它的**工具步骤事件会带命名空间转发给 UI**（`subagent:<描述>:<id>`），所以用户能看到"子代理在工作"，而父上下文只收到报告。

### 边界与停止
- **每次运行最多 4 个子代理**（`maxSubagents`），**每个子代理最多 6 轮**（`subagentMaxRounds`，小于父运行的 8 轮）。超预算**终止运行**（与轮次预算、"重复调用"守卫同类的 loop guard 语义），而不是静默拒绝，否则模型会一直要更多。
- 子代理**串行**执行：一轮里多个 `task` 调用按顺序跑。并行是模型可以要求的，但执行是顺序的——这是刻意的，避免与上面的写入并发问题同源的风险。
- **Stop 传播**：子代理共用父运行的 `AbortSignal`，父被取消时子代理一起停（有测试）。
- 子代理走**完全相同的门控路径**（bounded scope → preToolUse hooks → PermissionEngine → 审批 → 执行 → postToolUse hooks）；只有**执行体**不同。因此它自动获得与普通工具一致的取消处理、结果有界、步骤事件与后置 hook。

## Reasons
1. 与 CC / Codex 对照，subagents 是"扩展层补完之后"最自然的下一步，且它带来的**上下文隔离**是长会话里最实际的价值。
2. 用 `spawnsSubagent` 标记让 loop 拦截，而不是硬编码工具名——与既有的 `permissionEscalation` 是同一套模式（AGENTS.md 已明确禁止硬编码工具名匹配）。
3. 把子代理做成"普通工具 + 特殊执行体"而不是独立路径，避免出现第二套权限/事件/有界逻辑——那种分叉正是权限漏洞的温床。

## Consequences
- 子代理不能改代码，因此"让它去重构"这类用法不支持；它适合探索、定位、核对、收集证据。
- 报告上限 8000 字符：足够一份带路径的发现清单，不足以塞回整份文件。
- 未实现（明确记录，非遗漏）：可写子代理、并行执行、子代理之间的通信、子代理专属配置（模型/工具白名单/独立系统提示）、UI 的代理树视图（当前是带命名空间的步骤行）。
- 本机未验证：VS Code 内 F5 的真实子代理体验与模型是否会恰当使用 `task`。

## Verification
`test/subagents.test.js`（14 个）：输入契约（含长度上限与错误类型）、工具是 loop 拦截的标记且 `execute` 永不执行、简报写明三条规则、**报告是父收到的唯一内容**、**子代理只拿到任务与工作区上下文（不含父对话）且头部顺序正确**、**继承父运行模式**、**子代理够不到特权工具/升级工具/嵌套自身**（未知工具，退出码为 blocked）、**过滤后的工具目录恰好是只读观察者**、被阻塞的子代理以 `result.stopped` 回报而非成功、**预算超限终止运行**、**子代理活动带命名空间转发给 UI** 且 id 不与父 transcript 冲突、**取消传播**、畸形调用退化为工具失败、组合根注册守卫。

全量：**593 tests / 592 pass / 0 fail / 1 skip**（Skills 那一项时为 579）。

## 开发过程中的三次真实纠错（全部在测试侧）
1. 断言 `toolMessage.ok === false` 判断子代理失败，但 loop 把**执行成功**的工具包成 `{ok:true, result:{...}}`，子代理自身状态在 **`result.ok`**——断言写错（与 MCP 那次同源）。
2. 同一处第二例（`parentTool.ok`）同上。
3. 预算用例里每次循环发**完全相同**的 `task` 输入，于是"重复调用无进展"守卫**先于**预算守卫触发，拿到的是另一个（正确的）原因——改为每轮不同输入。

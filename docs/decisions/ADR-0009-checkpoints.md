# ADR-0009 — Checkpoints（回合检查点与回退）

## Status
Accepted

## Decision
新增**回合检查点**：每次用户请求开始时打一个边界，agent 在该回合内的所有文件改动都归属于它。用户可以回到任意一个检查点：**回滚代码**、**从此处分叉会话**，或**两者都做**（与参考实现提供的三个选项一致）。入口是命令 `yisiAI.checkpoints`（QuickPick）。

### 存什么（以及刻意不存什么）
只记录 agent **真正改过**的文件，每个改动保留**前/后文本**（有界），**不是整棵工作树的快照**。这是把编辑 journal 的"预算内捕获"思路拉长到整个会话，好处是**回退 = 一串具体的逆操作**，每一个都走既有的写入端口，因此**继承 stale guard**。

### 回退语义
- **回到检查点 K = 撤销 K 这一回合及其之后的所有改动**（`index >= K`）。检查点标记的是**回合开始**，所以"回到我提出那个请求之前"必须把该回合自己的改动也撤掉，否则答案会留在工作区里一半。
- 逆操作按**回合从新到旧、回合内从后到前**执行。
- **stale guard 是硬约束**：`rewriteTextFile` 以该改动留下的 `afterSha256` 作为期望版本；用户（或别的东西）在那之后改过文件 → **拒绝该文件并如实报告**，绝不覆盖用户的工作。
- **只有全部成功才忘记检查点**（`dropAfter`）。部分失败时**保留记录**并逐文件报告原因——一份与工作区静默不一致的记录比没有记录更糟，而且用户可能想重试。
- 回退**不走 agent 工具**：它是**用户**在撤销 agent，因此不受"只能重写本轮自建文件"这类 agent 专属限制；但工作区边界、敏感路径规则与 stale guard 全部保留。

### 分叉语义
分叉在检查点**之前**切开：新会话保留该回合请求之前的历史、继承模型/权限模式/执行工作区，并成为活动会话。标题为 `<回合标签> (fork)`，`titleSource: 'manual'`——一个用户主动创建的分支**不得**被自动命名覆盖。代码**原样保留**（回退是另一个显式选择）。

### 有界
`maxTurns: 12` / `maxChangesPerTurn: 40` / `maxTextBytes: 64KB`。任何放不下的东西都记成**不可回退 + 原因**（超限文本、命中回合改动上限、目录创建），而不是静默丢弃——与 journal 的 `reversibility` 语义一致。

### 已知限制（明确记录）
- **检查点存在内存里**：会话切换不丢（按 sessionId 分组），但**VS Code 重载后消失**。这与既有 `undo_last_edit`（journal 也在内存）一致，只是触达更远。把内容持久化与既有原则冲突——会话只存**引用**不存内容（附件就是这么处理的），要持久化需要先设计 sidecar 存储与其生命周期，属独立决定。
- 目录创建不可自动回退（删除目录不做自动化）。
- UI 是命令 + QuickPick；**消息悬停的 rewind 按钮未实现**（要改 webview 协议与客户端脚本，属 UI 打磨项）。

## Reasons
1. 与 CC / Codex 对照，"能回到任意更早的点"是既有单步 `undo_last_edit` 与本特性的真实差距；回合是用户能理解的最小单位。
2. 只记改动文件 + 逆操作，而不是快照：快照会带来存储与一致性两套新问题，而逆操作复用现有的写入端口、stale guard 与敏感路径规则。
3. 部分失败保留记录：这是仓库一贯的"宁可如实报告也不静默"的取舍。

## Verification
`test/checkpoints.test.js`（15 个）：回合顺序/标签/fork 点、无开启回合不记录、**回退计划的方向与顺序**、有界（超限文本与回合上限都记成不可回退并带原因）、`dropAfter`/`clearSession`；**经真实 `WorkspaceEditService` + 内存工作区**：回退恢复被改/被删/被建的文件、**一次回退跨多个改动**（这就是"超过单步 undo"的证据）、**用户改过的文件被拒绝且不被覆盖**、不可回退项如实报告、重命名反向回退；分叉（保留所选回合之前的历史、切换活动会话、继承模式与模型、标题不被自动命名覆盖、首个回合分叉得到空历史、未知检查点拒绝、标题有界）；组合根与 manifest 接线守卫。

全量：**608 tests / 607 pass / 0 fail / 1 skip**（Subagents 那一项时为 593）。

## 开发过程中的三次真实纠错
1. **回退语义写反了**：初版 `rewindPlan` 用 `index > K`，于是"回到最后一个检查点"是空操作。检查点标记回合开始，正确语义是 `index >= K`（含该回合）。测试先暴露了它（`outcome.failed[0]` 不存在），改成含该回合并同步改 `dropAfter`。
2. 测试辅助函数把 `oldText` 写成常量 `'x'`，与真实文件内容不符，导致第二次替换撞上 stale guard 而失败——**测试的假数据错了**。
3. 改完 `checkpointStore.ts` 后**没重新编译就跑测试**，于是跑的是旧的 `dist`——8 个用例假失败。重编译后全绿。

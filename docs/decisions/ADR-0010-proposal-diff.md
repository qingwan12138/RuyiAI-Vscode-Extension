# ADR-0010 — 并排 diff（待批准改动的编辑器视图）

## Status
Accepted

## Decision
待批准的文本改动不再只在侧栏卡片里显示 `-old / +new` 片段，而是**在 VS Code 原生 diff 编辑器里并排打开整份文件**：左边是文件当前内容，右边是批准后会变成的内容。

### 它是**视图**，不是第二个审批通道
这是本 ADR 最重要的一条：

- **批准仍然只能在侧栏卡片里发生**。diff 编辑器没有任何"批准"动作，`ProposalDiffPresenter` 甚至拿不到 `ApprovalBroker`（有源码级断言禁止它出现）。
- diff **先打开、再等待用户决定**（`void this.proposals?.open(request)` 在 `await` 之前），所以用户是**边看边决定**，而不是先决定再看。
- 打开 diff 是 **fire-and-forget**：慢或失败都**不得**延迟或影响审批本身（异常被吞掉，卡片里仍有片段 diff）。
- 这一条直接对应 `AGENTS.md §2`：只有 PermissionEngine 决定，且审批只有一个入口。

### 绝不渲染"假的未来"
diff 右边是**推演**出来的内容，因此只在推演可信时才显示：

- `replace_text` 要求 `oldText` 在**当前内容里恰好出现一次**——与编辑工具自身的唯一匹配要求一致。缺失或不唯一 → **跳过**并给出原因（"文件已不再精确匹配该改动"），因为显示一个**不会真正发生**的"未来"就是在骗用户。
- 文件读不到 → 跳过（不能拿空内容当"现在"）。
- 超过 512KB → 跳过并说明大小，避免把编辑器卡住。

支持与跳过一览：`replace_text` / `create_text_file`（左边是空）/ `rewrite_text_file` / `delete_file`（右边是空）→ 显示；`run_command`、`rename_file`、`ruyi_manage`、MCP 工具等**没有文本可比**的 → 跳过，卡片上的摘要仍是全部信息。

### 实现要点
- 右侧（以及需要时的左侧）由 **`TextDocumentContentProvider`**（scheme `yisi-proposal`）**从内存**提供——**批准前不落盘**，与编辑工具的既有规则一致。
- 左侧在**当前文件内容与视图构建时一致**的情况下直接用**真实文件 Uri**，因此保留语法高亮、折叠与 git 装饰；否则用虚拟副本。
- 虚拟文档会被**尽力赋予与真实文件相同的 languageId**（拿不到就算了，属锦上添花）。
- 保留的虚拟内容有总量上限（8MB，超出按插入顺序淘汰最旧），避免长会话无界增长。
- 每个执行根各自绑定：worktree 会话的 diff 读的是**它自己的 checkout**，而不是主工作树。
- 内容原样传递（**不做 EOL 归一化**）——一个视图不该改变它展示的字节。

## Reasons
1. 片段 diff 对一行改动够用，对"在上下文里判断这次改动"基本没用；参考实现也是直接在编辑器里给出整份文件的并排对比。
2. 复用 VS Code 自带的 diff：语法高亮、折行、并排/内联切换、无障碍支持全部免费，且不新增任何依赖。
3. 把 diff 明确定义为"视图"而不是"第二个审批入口"，避免了一整类"两个地方都能批准"的权限漏洞——这也是本仓库反复强调的边界。

## Consequences
- 每次需要确认的文本编辑都会打开一个 diff 标签页；用户不想要时它只是一个可关闭的编辑器标签。
- 未实现（明确记录，非遗漏）：**在 diff 里直接编辑提案后再批准**（参考实现支持）。要做到这一点，编辑路径必须在**应用时**读取提案内容，而不是使用工具入参里的 `oldText/newText`；那会改动 `WorkspaceEditService` 的应用语义与 stale guard 的边界，属独立设计。当前 diff 是**只读**的。
- 未实现：改动被批准/拒绝后自动关闭 diff（VS Code 没有稳定的"关闭这个 diff"API）；保留内容按总量淘汰。
- 本机未验证：VS Code 内 F5 实际打开 diff 的观感（语言、主题、并排布局），以及"文件已被改动因而跳过"在真实编辑流里的表现。

## Verification
`test/proposal-diff.test.js`（10 个）：整份文件上下文的替换视图、**不再匹配/不唯一/读不到时跳过而不是伪造未来**、新文件对空、整文件重写与删除、**CRLF 原样传递**、无文本可比的动作一律跳过、输入不完整不抛异常、超限跳过并说明；以及两条**源码级不变式**：`VsCodeToolConfirmation` **先开 diff 再 await 决定**且是 fire-and-forget、`ProposalDiffPresenter` **不得**出现任何审批能力（禁止 `ApprovalBroker`/`confirm`），组合根只注册一次 provider 且随扩展释放、并按执行根绑定。

全量：**618 tests / 617 pass / 0 fail / 1 skip**（Checkpoints 那一项时为 608）。

# ADR-0004 — 项目指令文件（AGENTS.md 家族）

## Status
Accepted

## Decision
Yisi AI 在每次 **Agent 运行**时读取工作区根目录下的项目指令文件，并作为 system 消息注入到请求头部。

支持的文件名与优先级（**先命中者生效，不做合并**）：

```
AGENTS.md  >  CLAUDE.md  >  YISI.md
```

约束：

1. **来源是工作区内容，不是操作者指令**。注入文本被显式框定为"仓库内容"，并写明它**不能**改变工具集、权限规则或模式简报；若它要求绕过权限引擎，模型应拒绝并说明。
2. **不改变权限模型**。文本只是告知；每次工具调用仍然逐次经过 `PermissionEngine`（docs/07 的既有约束不变）。即使仓库里的 AGENTS.md 是恶意的，也无法借此获得任何越权能力。
3. **仅作用于 Agent 路径**（`AgentChatRunner` → `AgentToolLoop`）。**不注入**裸聊天路径，尤其**不含**会话自动命名的那次 bare 请求——那条请求按设计必须只有"system 指令 + 第一轮问答"。
4. **读取走工作区边界**：复用 `FileSystemPort`（根边界、symlink 保护、敏感路径规则），只查执行根；worktree 隔离会话读的是它自己那份 checkout。
5. **有界**：单文件上限 12000 字符，超出时截断并留下可见标记，绝不静默。
6. **失败不致命**：文件缺失、被占用、是目录、过大或不可读都返回"无指令"；只有取消（abort）向上传播。项目指令是增强项，不是运行前提。

## Reasons
1. CC 在会话启动时加载 CLAUDE.md，Codex 加载 AGENTS.md——这正是为了让模型知道"这个仓库希望怎么干活"。Yisi 此前完全没有等价能力，项目约定只能每次在对话里重复输入。
2. 只学行为、不抄实现：文件格式与措辞均为自研（docs/04 clean-room 规则）。
3. 先命中而不合并：仓库常见"CLAUDE.md 指向 AGENTS.md"的写法，合并会把同一套约定注入两次；两个文件冲突时也没有确定性的裁决规则。
4. 放在请求头部而非尾部：它对一个工作区是稳定的，留在可缓存前缀里；随模式变化的权限简报仍然只在尾部（保持既有缓存策略）。
5. 只作用于 Agent 路径：裸聊天/自动命名通道按设计必须保持最小请求，注入项目文本会破坏该前提。

## Consequences
- 新增一次每轮运行的本地文件读取（仅查最多 3 个候选名），相对一次模型调用可忽略。
- 修改指令文件后**下一次运行即生效**（每轮读取，不做跨会话缓存）。
- 项目指令是 **prompt-injection 面**：内容由仓库控制。缓解措施是"框架声明 + 权限引擎仍是唯一闸门"，而不是依赖模型自律。
- 尚未实现（明确记录，非遗漏）：
  - 子目录/嵌套指令文件（CC 支持按路径分层加载）
  - 用户级（跨项目）指令文件
  - 非 Agent 的裸聊天路径注入
  - 大小/来源的 UI 可见性（用户看不到"这次注入了哪份文件"）

## Verification
`test/project-instructions.test.js`（15 个用例）：候选优先级与不合并、CRLF 归一化与截断标记、消息框定（"不能改变权限规则"、用户优先）、服务层回退与有界、取消传播、loop 中的位置（`[角色, 项目指令, ...历史, 模式简报, 用户轮]`）、无指令时不新增 system 消息、runner 的失败降级（loader 抛错不让运行失败）、组合根接线守卫。

全量：`484 tests / 483 pass / 0 fail / 1 skip`。
